`creem catalog promote` copies the store's test catalog (meters and products) into live, pairing items by key (`external_id`), and `creem catalog link` and `creem catalog unlink` pair and unpair a test and a live item by hand.

- `catalog promote` runs Creem's dry run first and follows `next_cursor` until the run is complete. In a terminal it asks for each `needs_key` item's key (a numbered list of live items with the same name, and the proposed key), for each feature that needs a key, and for each `possible_rename` (create, or re-pair with a live item), offers to copy live-only `metadata` keys into test, runs the dry run again after any of these writes, and asks before the real run. `--dry-run` previews only; `--yes` confirms the real run but never a key, and stops before it on a `possible_rename` unless `--create <test id>` names the item; `--force` writes the other items when the check refuses one; `--select meters=…|products=…` takes `all` or test ids. Every item's result, error code and message is printed with the `run_id`; `--json` prints `{ preview, run }`. The exit code is 4 when an item ends `failed`, `conflict`, `blocked` or `needs_key`.
- `catalog link --kind product|meter|feature` checks the key on both sides with a dry run, then writes live first and test second, and reports "Live written" when the test write fails; running it again finishes the pair. Without `--key` it proposes a key and asks; outside a terminal `--key` is required. A feature's key is written through each side's product, re-sending the product's other features of that type. `catalog unlink` clears the live item's key after confirmation.
- These commands use the store's live and test keys: `CREEM_LIVE_API_KEY` and `CREEM_TEST_API_KEY`, else the current key when it belongs to that environment. In a terminal a missing key is asked for and never saved; otherwise the command exits 3 and names the variable.
