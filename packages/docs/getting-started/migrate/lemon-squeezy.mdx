Lemon Squeezy closed new sign-ups on November 16, 2026 and stops processing payments, including subscription renewals, on March 31, 2027. Creem is a Merchant of Record like Lemon Squeezy, so you keep selling worldwide without registering for sales tax or VAT yourself. Your AI agent can do most of the move for you.

| Date              | Lemon Squeezy                                                                                  |
| ----------------- | ---------------------------------------------------------------------------------------------- |
| November 16, 2026 | Stopped accepting new stores                                                                   |
| Mid-January 2027  | Recommended latest date to start migrating. Lemon Squeezy says the move can take up to 8 weeks |
| March 31, 2027    | Stops processing payments, including subscription renewals. No extension is planned            |

Sources: [Saying goodbye to Lemon Squeezy](https://www.lemonsqueezy.com/blog/saying-goodbye-to-lemon-squeezy) and the [Lemon Squeezy migration guide](https://docs.lemonsqueezy.com/migration).

## Before you start

Four checks, about 5 minutes:

1. **What you sell is allowed.** Creem reviews every account before it takes live payments. See [account reviews](/merchant-of-record/account-reviews/account-reviews).
2. **Your country gets payouts.** Creem pays out to merchants in 88 countries. See [supported countries](/merchant-of-record/supported-countries).
3. **Your prices can be in USD or EUR.** If your Lemon Squeezy store uses another currency, decide your new prices first.
4. **Your customers can pay by card.** Creem's checkout takes cards, Apple Pay and Google Pay, but not PayPal. Lemon Squeezy can't move PayPal subscriptions to any provider, so those subscribers pay by card on Creem. See [payment methods](/merchant-of-record/finance/payment-methods).

## With your AI agent

This works with Claude Code, Codex, Cursor or any coding agent that can read web pages and work in your codebase.

<Steps>
  <Step title="Put your API keys in your environment">
    Create an API key in Lemon Squeezy under **Settings → API**, and a Creem test key
    (`creem_test_…`) in [test mode](/getting-started/test-mode). Set them as `LEMONSQUEEZY_API_KEY`
    and `CREEM_API_KEY` in the shell your agent uses. Never paste a key into the chat.
  </Step>
  <Step title="Give your agent the migration instructions">
    Open your agent in your app's repository and paste:

    ```text
    Migrate this app's Lemon Squeezy store to Creem.

    Follow https://docs.creem.io/getting-started/migrate/lemon-squeezy/technical-guide.md
    and the migration prompt in it.

    - My keys are in LEMONSQUEEZY_API_KEY and CREEM_API_KEY. Never print, log or commit them.
    - Use Creem test mode (https://test-api.creem.io) until I approve going live.
    - Start with a read-only inventory of my Lemon Squeezy store and this codebase, then show
      me a plan. Don't create, change or cancel anything until I approve it.
    ```

  </Step>
  <Step title="Review the plan, then let it run">
    Your agent shows what it will create, what you finish in the dashboard and what can't move.
    Once you approve, it rebuilds your catalog and customers in test mode, switches new sales to
    Creem in your code, and lists your subscribers by renewal date.
  </Step>
  <Step title="Go live">
    Once your account is approved, create a live API key and ask your agent to run the import again
    with it. Your existing subscribers move after that, one at a time, close to their renewal date.
  </Step>
</Steps>

<Info>
  **A Lemon Squeezy migration skill is on its way.** Install it once and your agent knows the whole
  migration, with no prompt to paste. Until then, the prompt above gives your agent the same rules.
</Info>

<Tip>

  your Creem store while it works.
</Tip>

## With the Creem CLI

For your catalog, the [Creem CLI](/code/cli) copies products, product groups, discount codes, license key settings and files in one command. It reads your Lemon Squeezy store and the Creem store you're logged in to, has Creem check the plan with a dry run, prints what it creates, updates and skips, and writes only after you confirm. Your Lemon Squeezy API key stays on your machine.

```bash
brew tap armitage-labs/creem
brew install creem
creem login --api-key creem_test_YOUR_KEY
creem migrate lemon-squeezy --dry-run
creem migrate lemon-squeezy
```

| Option                | What it does                                                                  |
| --------------------- | ----------------------------------------------------------------------------- |
| `--ls-api-key <key>`  | Your Lemon Squeezy API key                                                    |
| `--ls-store-id <id>`  | The Lemon Squeezy store to read                                               |
| `--dry-run`           | Has Creem check the plan with a dry run, prints it and writes nothing         |
| `--yes`               | Writes without asking. Required when no terminal is attached                  |
| `--adopt [answers]`   | Answers adoption proposals (below)                                            |
| `--force`             | Writes even when Creem's check refuses items, and leaves those items out      |
| `--exclude-discounts` | Copies everything except discount codes                                       |
| `--json`              | Prints the plan as a JSON report. With `--yes`, runs it and prints the result |

### Running it again

Every object the CLI writes carries a key in `external_id`: `ls_variant_<id>` for products, `ls_product_<id>` for product groups and `ls_discount_<id>` for discounts. Each one is written with Creem's keyed upsert, which creates the object when its key is new and otherwise changes only the fields the CLI sends, so a run that stopped halfway, a run in test mode followed by one with a live key, or two runs at the same time never create an object twice. When nothing changed, the plan lists every item as unchanged and nothing is written. A store migrated by an earlier version of the CLI is found the same way; the only new writes are its product groups, which that version left to you.

### Creem checks the plan first

Before the first write, Creem checks the whole plan without writing anything: the products together in one validation, so a rule that spans products is checked too, and each product group and discount with a dry run. The plan shows what Creem would do with each item, and an item Creem refuses carries Creem's error and a hint. When Creem refuses an item, nothing is written and the command exits with `8`; fix what the error says and run it again, or pass `--force` to write everything else and leave the refused items out. During the run, every write runs as a dry run once more right before it, with the IDs of the files and products the run just wrote. `--dry-run` is this check alone. Files have no dry run: they are uploaded during the run only.

A Creem product without a key that has the same name as a variant, ignoring case and spacing, or a discount with the same code, is proposed for adoption. The plan shows how each candidate differs, for example its price or currency, and never picks one for you. In a terminal the CLI asks about each candidate: yes gives it the key, no to all of them creates a new product. Without a terminal, answer with `--adopt ls_variant_123=prod_abc` to adopt that product, `--adopt ls_variant_123=new` to create a new one, or `--adopt` alone to adopt every proposal that has exactly one candidate. `--adopt ls_variant_123=prod_abc` also adopts a product without a key whose name differs, for example one you renamed. `--yes` never answers a proposal: while one is unanswered, the run writes nothing and exits with `7`, and so do `--dry-run` and `--json` without `--yes`, so a script knows the run would stop. An answer the CLI can't apply, for a key the plan doesn't have, a product that already has a key, or a product another answer already adopts, stops the command with exit code `2` before it asks or writes anything.

### What the CLI copies

- One product per variant: name (product name plus variant name when a product has several), description as plain text, price and currency, one-time or recurring, billing cycle (weekly and other cycles become a custom cycle), trial in days, and tax category.
- Free one-time variants as free products, and pay-what-you-want one-time variants with their minimum and suggested price.
- License key settings as a license key feature, with the activation limit and expiry.
- Files as file downloads on the product. A re-run uploads a file again only when its contents changed. The API can't show the contents of a file you uploaded yourself, so a file of yours is never taken as the Lemon Squeezy file, even with the same name: the Lemon Squeezy file is added next to it, and the plan says so.
- Published discount codes. A code limited to some variants applies to those products; any other code applies to every migrated product. A code with a redemption limit gets what's left of it, because Creem counts redemptions from zero: the CLI reads how many are used in Lemon Squeezy. While Lemon Squeezy still sells, a re-run lowers the limit to match, but never below what Creem has already redeemed.

It skips, with the reason in the plan: free subscriptions, usage-based and tiered prices, billing cycles Creem doesn't support, pay what you want with a minimum below 1.00, draft variants, draft and expired discount codes, codes whose redemption limit is used up, codes longer than 14 characters, files that couldn't be downloaded, and the hidden default variant of a product that has other variants. Discount names longer than 40 characters are shortened. Pay-what-you-want subscriptions get their minimum price as a fixed price, because pay what you want is one-time only in Creem. Images aren't copied.

A Creem product that carries a variant's key but isn't migrated any more, because the variant was deleted or is now a draft, stays as it is and is listed with an `orphaned` warning. Archive it in Creem if it shouldn't sell. The same goes for an active Creem discount whose Lemon Squeezy code was deleted, or is now a draft, expired or used up: buyers can still redeem it, so expire or delete it in Creem if they shouldn't. The CLI never removes products, features, files or products from a migrated discount. When Lemon Squeezy no longer applies a discount to a migrated product, the CLI can't tell that from a product you added in Creem, so the product stays on the discount with a `discount_product_kept` warning; remove it in Creem if the discount shouldn't apply.

The CLI also creates a product group for each Lemon Squeezy product with two or more subscription variants, so customers can switch between them, and keeps its products in the Lemon Squeezy order on a re-run. If you already made that group in the dashboard, Creem refuses the new one because its products are taken, and the plan names the command that gives your group the key instead: `creem product-groups update <group id> --external-id ls_product_<id>`. Customers, subscriptions, orders and issued license keys aren't migrated; the [technical guide](/getting-started/migrate/lemon-squeezy/technical-guide) covers them.

<Warning>
  Each run, dry runs included, downloads every published file once to compare it with the copy in
  Creem. Lemon Squeezy allows 10 downloads of a file per day from one IP address.
</Warning>

With `--json`, the report lists every item with its action, its Creem ID, and the reason or error. The exit code is `0` when every item went through, `1` when Creem answered a dry run as a real write (the CLI stops there), `2` for invalid options, an `--adopt` answer that can't be applied, or a missing API key, `4` when part of the Lemon Squeezy store couldn't be read, `6` when the run finished with failed items, `7` when an adoption proposal is unanswered, and `8` when Creem's check refused an item; `7` and `8` also for `--dry-run` and a `--json` plan. Nothing is written with `2`, `4`, `7` or `8`. Fix what the report names and run the command again.

## What moves

| Moves to Creem                                                                                                                                                                                                                                                                                                              | Doesn't move yet                                                                                          |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Products and prices, discount codes, license key settings and file downloads, with the CLI or the Creem team. Customers, with the Creem team or your own import; the CLI doesn't copy customers. Product groups, with the CLI. You point webhooks and checkout links at Creem, and set affiliates up again in the dashboard | Active subscriptions and saved cards, existing license keys, order history and affiliate referral history |

**Existing subscribers** move one at a time: each one checks out once on Creem, close to their Lemon Squeezy renewal date, so nobody pays twice. A direct import that keeps their renewal date is in development. See [Move existing subscribers](/getting-started/migrate/lemon-squeezy/technical-guide#6-move-existing-subscribers).

## FAQ

<AccordionGroup>
  <Accordion title="Do my subscribers need to enter their card again?">
    Yes, for now. Each subscriber checks out once on Creem. Time it close to their Lemon Squeezy
    renewal date so they don't pay twice for the same period.
  </Accordion>
  <Accordion title="Can my customers keep their license keys?">
    Not on Creem: Creem issues new keys for purchases on Creem. Keep validating Lemon Squeezy keys
    in your backend until those customers move.
  </Accordion>
  <Accordion title="What happens to my order history?">
    It stays in Lemon Squeezy. Export it as CSV before March 31, 2027. Creem shows only the orders
    it processes.
  </Accordion>
  <Accordion title="Does importing customers notify them?">
    No. Creating a customer in Creem sends no email and creates no order.
  </Accordion>
  <Accordion title="Do I need to finish before March 31, 2027?">
    Move new sales well before then. Every subscriber should have moved by that date: Lemon Squeezy
    stops processing renewals on March 31, 2027 and doesn't plan to extend it.
  </Accordion>
</AccordionGroup>
