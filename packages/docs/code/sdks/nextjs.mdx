`@creem_io/nextjs` is a small App Router adapter around the Creem SDK. It provides route-handler
factories for checkout, the customer portal, and webhooks, plus React link components for starting
checkout or opening the portal.

## Create a checkout route

Keep the API key on the server:

```bash .env.local
CREEM_API_KEY=creem_test_...
CREEM_WEBHOOK_SECRET=whsec_...
```

Create the route used by the checkout component:

```typescript app/checkout/route.ts
import { Checkout } from "@creem_io/nextjs";

export const GET = Checkout({
  apiKey: process.env.CREEM_API_KEY!,
  testMode: true,
  defaultSuccessUrl: "/billing/success",
});
```

Render a link to that route:

```tsx app/pricing/page.tsx
import { CreemCheckout } from "@creem_io/nextjs";

export default function PricingPage() {
  return <CreemCheckout productId="prod_...">Subscribe</CreemCheckout>;
}
```

`CreemCheckout` builds an anchor whose query parameters are consumed by `Checkout`. It supports:

| Prop           | Required | Description                                         |
| -------------- | -------- | --------------------------------------------------- |
| `productId`    | Yes      | Creem product ID.                                   |
| `requestId`    | No       | Idempotency key for the checkout request.           |
| `units`        | No       | Number of units to purchase.                        |
| `discountCode` | No       | Discount code applied at checkout.                  |
| `customer`     | No       | Customer email and name.                            |
| `customFields` | No       | Array of text or checkbox fields shown at checkout. |
| `successUrl`   | No       | Return URL after checkout.                          |
| `metadata`     | No       | Application metadata stored on the checkout.        |
| `referenceId`  | No       | Application user or account ID added to metadata.   |
| `checkoutPath` | No       | Route path; defaults to `/checkout`.                |

<Warning>
  Component props become client-controlled query parameters. For authenticated billing, wrap the
  checkout handler and derive `customer`, `referenceId`, `requestId`, allowed product IDs, and the
  success URL from trusted server-side state. Do not use query parameters as proof of identity or
  entitlement.
</Warning>

### Protect an authenticated checkout

The route below accepts the selected product from the link, checks it against a server-side
allowlist, and replaces identity-related parameters with values from the authenticated session.
`successUrl` is removed from the request so the handler always uses the server-configured default.

```typescript app/checkout/route.ts
import { Checkout } from "@creem_io/nextjs";
import { NextRequest, NextResponse } from "next/server";

const allowedProductIds = new Set(["prod_starter", "prod_pro"]);

const checkout = Checkout({
  apiKey: process.env.CREEM_API_KEY!,
  testMode: true,
  defaultSuccessUrl: "/billing/success",
});

export async function GET(request: NextRequest) {
  const user = await requireUser(request);
  const productId = request.nextUrl.searchParams.get("productId");

  if (!productId || !allowedProductIds.has(productId)) {
    return NextResponse.json({ error: "Invalid product" }, { status: 400 });
  }

  const requestId = await getOrCreateCheckoutAttemptId(user.id, productId);
  const url = request.nextUrl.clone();
  url.searchParams.set(
    "customer",
    JSON.stringify({ email: user.email, name: user.name ?? undefined }),
  );
  url.searchParams.set("referenceId", user.id);
  url.searchParams.set("requestId", requestId);
  url.searchParams.delete("successUrl");

  return checkout(
    new NextRequest(url, {
      headers: request.headers,
    }),
  );
}
```

`requireUser` represents your application's server-side authentication check. It should reject an
unauthenticated request and return the user from the verified session.
`getOrCreateCheckoutAttemptId` represents a server-side idempotency record: retries of one purchase
attempt should reuse its ID, while a later intentional purchase gets a new one. Validate or
overwrite other commercial inputs, such as `units` and `discountCode`, when customers should not
be able to choose them freely.

## Create a customer portal route

```typescript app/portal/route.ts
import { Portal } from "@creem_io/nextjs";

export const GET = Portal({
  apiKey: process.env.CREEM_API_KEY!,
  testMode: true,
});
```

```tsx
import { CreemPortal } from "@creem_io/nextjs";

<CreemPortal customerId="cust_...">Manage billing</CreemPortal>;
```

`CreemPortal` uses `/portal` by default. Set `portalPath` when your route lives elsewhere.

<Warning>
  The portal handler accepts a customer ID from the URL and does not authenticate it. Before using
  this pattern in an application, require a session and verify that the requested customer belongs
  to the signed-in account. Never expose an unprotected portal route.
</Warning>

## Handle webhooks

Create a POST route and register its public URL in the Creem dashboard:

```typescript app/api/webhook/creem/route.ts
import { Webhook } from "@creem_io/nextjs";

export const POST = Webhook({
  webhookSecret: process.env.CREEM_WEBHOOK_SECRET!,
  onGrantAccess: async ({ reason, metadata, product }) => {
    const userId = metadata?.referenceId;
    if (typeof userId !== "string") return;

    await setProductAccess({ userId, productId: product.id, enabled: true, reason });
  },
  onRevokeAccess: async ({ reason, metadata, product }) => {
    const userId = metadata?.referenceId;
    if (typeof userId !== "string") return;

    await setProductAccess({ userId, productId: product.id, enabled: false, reason });
  },
});
```

`Webhook` reads the raw request body, verifies the `creem-signature` header, parses the event, and
calls the matching handler. Keep every callback idempotent because delivery may be retried.

### Access callbacks

`onGrantAccess` runs for active, trialing, and paid subscription events. `onRevokeAccess` runs when
a subscription is paused or expired. A scheduled cancellation does not revoke access immediately;
the subscription remains usable through the end of its current period.

### Event callbacks

The adapter also exposes callbacks for individual events:

- `onCheckoutCompleted`
- `onRefundCreated`
- `onDisputeCreated`
- `onSubscriptionActive`
- `onSubscriptionTrialing`
- `onSubscriptionCanceled`
- `onSubscriptionPaid`
- `onSubscriptionExpired`
- `onSubscriptionUnpaid`
- `onSubscriptionUpdate`
- `onSubscriptionPastDue`
- `onSubscriptionPaused`
- `onSubscriptionScheduledCancel`

Each callback receives normalized event data, including `webhookId`, `webhookCreatedAt`, and the
relevant customer, product, order, or subscription fields.

## Route factory reference

### `Checkout(options)`

| Option              | Type      | Default  | Description                            |
| ------------------- | --------- | -------- | -------------------------------------- |
| `apiKey`            | `string`  | Required | Server-side Creem API key.             |
| `testMode`          | `boolean` | `false`  | Uses the Creem test API.               |
| `defaultSuccessUrl` | `string`  | —        | Return URL when the request omits one. |

### `Portal(options)`

| Option     | Type      | Default  | Description                |
| ---------- | --------- | -------- | -------------------------- |
| `apiKey`   | `string`  | Required | Server-side Creem API key. |
| `testMode` | `boolean` | `false`  | Uses the Creem test API.   |

### `Webhook(options)`

`webhookSecret` is required. All event and access callbacks are optional.
