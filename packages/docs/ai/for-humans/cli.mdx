title: Creem CLI
description: Browse your Creem store interactively and discover every SDK operation from the terminal.
---

Install the CLI with Node.js 22 or newer and log in using the masked key prompt:

```sh
npm install -g @creem_io/cli
creem login
creem whoami
```

Homebrew users can run `brew tap armitage-labs/creem` and `brew install creem`. Verify the installed version with `creem --version`.

## Interactive browsing

Open products, customers, subscriptions, or transactions without a subcommand:

```sh
creem products
creem customers
creem subscriptions
creem transactions
```

Use arrows or `j`/`k` to move, Enter for details, `/` to search, and `q` to quit. The command bar supports customer billing links and subscription cancellation, pause, and resume. Destructive actions require confirmation. The TUI displays your test/live environment.

## Scriptable commands

All 55 generated SDK operations are also available as terminal commands, including customer credits, licenses, affiliates and invitations, revenue splits, moderation, and refunds. Use the shared [command reference](/code/cli#command-reference) and append `--help` to discover flags.

```sh
creem products create --name Free --description 'Free download' --price 0 --currency USD --billing-type onetime
creem checkouts create --product prod_123 --customer-email person@example.com
creem affiliates list
creem splits list
creem stats summary --currency USD
```

For complex bodies, use `--data @request.json` with SDK camelCase fields. Use `--json` for machine-readable results or `--all --output ndjson` to export every list item. See [request bodies and pagination](/code/cli#request-bodies).

## Environments and errors

The API key determines test/live mode. `CREEM_API_KEY` takes precedence over local login and is not saved. A conflicting `--environment` fails before an API call. Local credentials use a protected configuration file; `creem logout` removes the stored key.

Errors explain the problem, a repair step, and the trace ID when provided by the API. Interactive destructive actions show TEST or LIVE before confirmation; scripts and JSON output require `--yes`. Check write outcomes before retrying, because the CLI never retries writes automatically.

Subscription and discount lists now use the SDK's authoritative search endpoints. SDK parity covers public generated operations; dashboard-only and ungenerated metering capabilities remain outside the current CLI baseline.
