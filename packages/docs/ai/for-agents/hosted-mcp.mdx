Creem runs an [MCP](https://modelcontextprotocol.io) server at `https://mcp.creem.io/mcp`. Add it to ChatGPT, Claude Code or Codex, sign in with your Creem account, and your agent can look up customers, subscriptions and payments, create products, checkout links and discount codes, cancel subscriptions and issue refunds. There is nothing to install and no API key to paste.

<Tip>
  **Hosted or local?** The hosted server signs you in with your Creem account and asks you to
  confirm before risky actions. The [local MCP server](/ai/for-agents/mcp-server) runs on your
  machine with an API key and exposes the whole API. Use it for scripts, CI and clients the hosted
  server doesn't support yet.
</Tip>

## Requirements

- A Creem account with at least one store ([sign up](https://creem.io/dashboard))
- ChatGPT, Claude Code, or Codex 0.147 or newer

Other clients, such as Claude.ai, Claude Desktop, Cursor and VS Code, can't sign in yet. Use the [local MCP server](/ai/for-agents/mcp-server) with them.

## Quickstart

```bash
claude mcp add --transport http creem https://mcp.creem.io/mcp
```

Then run `/mcp` in Claude Code, select **creem** and choose **Authenticate**. Your browser opens the Creem sign-in. For ChatGPT and Codex, see below.

## Claude Code

```bash
claude mcp add --transport http creem https://mcp.creem.io/mcp
```

`--transport http` is required: without it, Claude Code treats the URL as a local command. Add `--scope user` to use Creem in every project.

## ChatGPT

Custom MCP servers work in ChatGPT on the web, and your plan or workspace has to allow them. See OpenAI's [Connecting custom MCP servers in ChatGPT](https://help.openai.com/en/articles/12584461-developer-mode-apps-and-full-mcp-connectors-in-chatgpt).

<Steps>
  <Step title="Add the server">
    Go to [ChatGPT Plugins](https://chatgpt.com/plugins), select the plus button, then **Add custom
    MCP server**. Name it `Creem` and enter `https://mcp.creem.io/mcp` under **Connection**.
  </Step>
  <Step title="Choose OAuth">
    Choose **OAuth** and leave the client ID and secret empty. Review the risk warning, tick **I
    understand and want to continue**, then select **Create as a plugin**.
  </Step>
  <Step title="Sign in">
    Install the plugin and sign in with your Creem account when ChatGPT asks.
  </Step>
</Steps>

## Codex

```bash
codex mcp add creem --url https://mcp.creem.io/mcp
codex mcp login creem
```

`codex mcp login` opens your browser for the Creem sign-in. The Codex CLI, the IDE extension and the ChatGPT desktop app share one configuration, so adding the server once works in all three.

## Sign-in and permissions

When you connect, your browser opens Creem's sign-in and consent screen. You sign in, pick a store and a [mode](#test-and-live-mode), and choose what the agent can do. A connection works on one store; picking another store later replaces it.

Only **View your store** is ticked on a first connect. Tick the others the agent needs:

| Permission                                        | What it allows                                                                                                                |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **View your store**                               | Read products, checkouts, discount codes, customers, transactions, subscriptions, disputes, revenue and your business details |
| **Manage products, checkout links and discounts** | Create, edit and archive products, create checkout links, and create and delete discount codes                                |
| **Manage subscriptions**                          | Cancel your customers' subscriptions                                                                                          |
| **Issue refunds**                                 | Refund your customers' payments                                                                                               |

A tool outside the granted permissions fails with `missing scope`, for example `missing scope: refunds:write`. To add a permission, connect again from your client: the consent screen keeps what you already allowed and offers the rest.

When you grant a permission that changes your store, the consent screen also shows **Confirmations**: **Ask before risky actions**, ticked by default. Leave it ticked unless you trust the agent to act without asking. See [Security](#security).

You, and the store owner if that's someone else, get an email when an agent is connected or gets new permissions.

## Test and live mode

Each connection works in one mode at a time. **Test mode** uses your store's [test mode](/getting-started/test-mode) data, and no real money moves. **Live mode** works on real payments, refunds and subscriptions.

You choose the mode on the consent screen. **Live** is preselected when your store is approved for live payments. Every tool result says which mode it ran in, and every confirmation starts with `[Test mode]` or `[LIVE mode]`.

To change mode later, ask your agent (for example "switch Creem to live mode") or use **Settings → Connected apps** in the dashboard. Switching to live asks you to confirm.

## Available tools

25 tools, the same in both modes.

| Group             | Count | Tools                                                                                      |
| ----------------- | ----- | ------------------------------------------------------------------------------------------ |
| **Products**      | 5     | `list_products`, `get_product`, `create_product`, `update_product`, `archive_product`      |
| **Checkouts**     | 2     | `get_checkout`, `create_checkout_link`                                                     |
| **Discounts**     | 4     | `list_discounts`, `get_discount`, `create_discount`, `delete_discount`                     |
| **Customers**     | 2     | `search_customers`, `get_customer`                                                         |
| **Subscriptions** | 3     | `list_subscriptions`, `get_subscription`, `cancel_subscription`                            |
| **Transactions**  | 2     | `list_transactions`, `issue_refund`                                                        |
| **Disputes**      | 2     | `list_disputes`, `get_dispute`                                                             |
| **Stats**         | 1     | `get_revenue_summary`                                                                      |
| **Onboarding**    | 3     | `get_business_details_requirements`, `open_business_details`, `open_identity_verification` |
| **Connection**    | 1     | `switch_mode`                                                                              |

`get_business_details_requirements` shows what your store's business details still need, the first step to live payments. It works in live mode only. The two `open_` tools return a dashboard link, where you fill in the form yourself.

## Security

Some tools change your store and can't be undone. By default, Creem asks **you**, not the agent, to confirm them before anything happens.

| Tool                  | Asks you to confirm                                                                          |
| --------------------- | -------------------------------------------------------------------------------------------- |
| `issue_refund`        | Yes, unless you turn confirmations off                                                       |
| `cancel_subscription` | Yes, unless you turn confirmations off                                                       |
| `create_discount`     | Yes, unless you turn confirmations off                                                       |
| `delete_discount`     | Yes, unless you turn confirmations off                                                       |
| `archive_product`     | Yes, unless you turn confirmations off                                                       |
| `update_product`      | When it changes the price, currency, trial or success URL, unless you turn confirmations off |
| `switch_mode`         | Always when switching to live, even with confirmations off                                   |

Clients that can show a prompt display it with **Accept** and **Decline**. In other clients, the agent shows you the question in the chat and runs the tool only after you reply "yes". A confirmation covers exactly that action, works once and expires after 10 minutes.

To let a connection act without asking, turn off **Ask before risky actions** for it in [Connected apps](#connected-apps). The setting applies to that connection only, in test and live mode.

<Warning>
  With confirmations off, the agent may also act on text your buyers wrote, such as a customer name,
  without asking you. Someone could hide instructions in that text. Creem recommends keeping
  confirmations on.
</Warning>

Two more things to do:

**Develop in test mode.** Connect in test mode while you try things out. Nothing you break is real.

**Grant only the permissions you need.** An agent that only reports on your store needs **View your store** and nothing else.

## Connected apps

**Settings → Connected apps** in the dashboard lists the agents connected to your store, who connected them, their mode and whether they ask before risky actions. There you can:

- switch a connection between test and live mode
- turn **Ask before risky actions** on or off with **Change**. The change takes effect within a minute
- disconnect a connection

You can manage the connections you made; the store owner can manage all of them. Connecting the same app again keeps its current confirmation setting, so change it here.

A disconnected agent has to sign in again. Changes it already made, such as refunds or new products, stay.

## Limits

| Limit                  | Per connection | Per store |
| ---------------------- | -------------- | --------- |
| Calls per minute       | 120            | 300       |
| Write calls per minute | 30             | 60        |

Store limits count test-mode and live-mode calls separately. A call over a limit fails with `rate_limited` and changes nothing. Wait for the minute to pass and try again.

## Verifying it works

Connect in test mode and ask your agent:

```
List my Creem products.
```

The result ends with `Ran in test mode: test data, no real money.` If you get an error instead, see below.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Sign-in fails with invalid_client">
    Your client can't sign in to the hosted server yet. See [Requirements](#requirements), or use
    the [local MCP server](/ai/for-agents/mcp-server).
  </Accordion>
  <Accordion title="Every call fails with “The Creem MCP isn't enabled for this store yet”">
    The hosted server isn't enabled for your store. Contact [support](mailto:support@creem.io). Once
    it's enabled, the same connection works without signing in again.
  </Accordion>
  <Accordion title="A tool fails with missing scope">
    The connection doesn't have the permission the tool needs. Connect again and tick it on the
    consent screen. See [Sign-in and permissions](#sign-in-and-permissions).
  </Accordion>
  <Accordion title="My client asks me to sign in again">
    The connection was disconnected in Connected apps, by you or by the store owner. Sign in again
    to create a new connection.
  </Accordion>
  <Accordion title="A call fails with rate_limited">
    See [Limits](#limits). Wait for the minute to pass and try again.
  </Accordion>
  <Accordion title="A call fails with unavailable">
    Creem couldn't complete the call. Try again in a moment. If it was a write, check whether it ran
    first, for example with `list_transactions` after a refund.
  </Accordion>
</AccordionGroup>
